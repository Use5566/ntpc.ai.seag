回傳單一合法 JSON 物件。所有欄位必填；沒有項目時使用 []；未知日期用空字串。不可新增欄位。
本格式供模型回傳使用。正文使用 sections 陣列，每項把段落文字與來源放在一起；不要另外輸出 body 或 sourceMap。伺服器會依序組成正文並建立 S 編號，避免空白行與標題造成來源對照筆數不同。
以下為結構示例，P 編號與內容均須依實際輸入替換：
{
  "title": "中性知識稿標題",
  "sections": [
    {"text": "主題一\n完整描述性段落。", "sourceIds": ["P001"], "kind": "source"}
  ],
  "metadata": {
    "eventDate": "", "contentType": "研習逐字稿整理", "topics": ["主題"],
    "summary": "整體內容摘要", "limitations": [], "domains": [], "gradeBands": [],
    "usageLicense": "", "visibility": "token_holders"
  },
  "omissions": [], "questions": [], "privacyCandidates": [],
  "coverage": [{"sourceId": "P001", "status": "retained", "target": "主題一"}]
}
sections 每項只有 text、sourceIds、kind。來源內容 kind 為 source，sourceIds 至少一個有效 P 編號。不同來源的段落請拆成不同項目；標題和條列可留在同項目中。不省略重要細節。
僅當提供者事後補充且沒有逐字稿依據時，kind 使用 supplement，sourceIds 使用 []。不可用 supplement 規避來源對照。
metadata 不得有 hostOrganization、participantRoles、speakers、schemaVersion 或其他額外欄位。domains 是教材領域；gradeBands 是教材適用年段，不是參與者身分。usageLicense 固定空字串，留給使用者確認。visibility 固定 token_holders。
日期可為 YYYY、YYYY-MM、YYYY-MM-DD 或空字串；不得補猜。
omissions 每項格式：{"id":"O001","sourceIds":["P001"],"text":"完全捨棄且已去識別的內容","reason":"捨棄原因"}。
questions 每項格式：{"id":"Q001","sourceIds":["P001"],"question":"需確認的問題","context":"疑點脈絡，不洩漏身分"}。
privacyCandidates 每項格式：{"id":"D001","sourceIds":["P001"],"text":"來源中的精確識別文字","replacement":"[識別D001]","reason":"建議原因"}。同一 text 必須逐字出現在每個列出的 sourceIds 中。不同位置的文字不可拼接；不補字、不改標點、不加省略號。候選 id 從 D001 起，replacement 必須配對。
coverage 必須涵蓋全部來源，每個 sourceId 恰好一次。status 僅可為 retained、merged、omitted、pending。retained／merged 的 target 填正文主題；omitted 的 target 必須是該來源的 O 編號；pending 的 target 必須是該來源的 Q 編號。
所有 P 編號只可來自輸入；O、Q、D 編號各自唯一。正文、metadata、捨棄清單與問題中的識別候選暫用 replacement 代稱，只有 privacyCandidates.text 保留原文。

整理稿的標題與 sections.text 只含可閱讀的正文，不得寫入 [P001, P002] 等來源段落編碼；所有來源編號僅放在 sourceIds 等專用欄位。每個 section 以一個完整知識點為單位，不需逐一重寫每個原始段落。同一知識點的連續原文可合理合併，sourceIds 只列真正支持該知識點的來源。避免重複正文、重複大段原文或多餘排版空白，但不得為縮短輸出而刪除重要細節。
